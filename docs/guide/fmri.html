EDNiX · FUNCTIONAL MRI

From raw BOLD to cleaned residuals, common spaces and connectivity products

This page is written for a beginner who needs to understand what happens to each BOLD run, and for a developer who needs to trace the exact script, directory and derivative that implements each stage. It follows execution order, not alphabetical file order.

Source-of-truth rule: stage order, filenames, transform routing, cleanup behaviour and directory structure were checked against the EDNiX repository (modalities/fMRI, Tools/getpath.py, master, 13 November 2026). Run the ANAT pipeline first. Every parameter is listed in the functional parameter reference.

What must exist before fMRI processing starts?

The fMRI pipeline is not independent of ANAT. Its central job is to clean BOLD while preserving a reliable bridge to anatomy, atlases and group/reference space.

Required: BOLD runs

One or more BIDS-compatible 4D functional images. Sidecar metadata should contain TR, slice timing and phase-encoding information when available.

sub-*/ses-*/func/*bold.nii.gz + *.json

Preferred: processed subject anatomy

EDNiX retrieves an ACPC anatomical image, brain mask and tissue masks from ANAT. If the current session lacks anatomy, chooseanat.py can search the subject’s other sessions.

anat/native/volumes/*_space-acpc_desc-template_*.nii.gz

Alternative: template anatomy

When IhaveanANAT=False, the launcher can use a species/reference anatomy folder containing a skull-stripped reference and masks.

folderforTemplate_Anat/

Optional: field maps

EDNiX changes the distortion-correction route depending on whether it finds 0, 1, 2 or more field-map files and whether their headers/metadata are usable.

sub-*/ses-*/fmap/
Connection to the ANAT guide: fMRI reuses ANAT outputs rather than recomputing anatomy. In particular, the anatomical image, brain/tissue masks, atlas labels and ANAT transformation package become spatial scaffolding for Steps 3, 5 and 9.

The four spaces to remember

Most confusion in EDNiX fMRI comes from filenames that are scientifically reasonable but easy to blur together. Keep these four spaces mentally separate.

1. raw / space-func

Early BOLD-processing geometry. Trimming, despiking, slice timing, motion correction, run alignment and the first functional mask live here.

func/raw/

2. acpc-func

The main functional ACPC processing geometry after the anatomy↔functional bridge. Canonical cleaned residuals, FC matrices and the default seed-analysis space live here.

func/acpc-func/

3. acpc-anat

The anatomical ACPC frame. Step 8 exports cleaned BOLD here for anatomy-space work.

func/acpc-anat/

4. templates/<reference>

The common atlas/reference frame. Step 9 exports cleaned BOLD, masks and labels here for common-space analyses and final visual QC.

func/templates/<reference>/
One BOLD run can therefore exist several times. The suffix tells you not only what processing happened, but also which coordinate frame the data currently occupy. Do not compare two files simply because both end in residual.nii.gz.

How the launcher chooses the field-map route

The field-map branch is selected before Step 2. The internal state names are historical, so the documentation translates them into what they mean operationally.

0 field maps → very_old

No field-map distortion correction. Step 2 copies the N4 run mean into the unwarped filename so later stages retain one stable contract.

runMean_n4Bias → runMean_unwarped

1 field map → old / very_old

One-map legacy route when the file is usable; incompatible metadata/header conditions can fall back to no correction.

single-fieldmap preparation + FUGUE

2 field maps → 2_mapdir

Direction-pair route. EDNiX keeps track of the mapping/correction direction and prepares the appropriate field-map products for Step 2.

paired map-direction route

>2 field maps → new

Newer multi-fieldmap layout. The launcher filters/selects field maps for the functional runs instead of assuming one global map.

run-aware fieldmap selection
Beginner rule: field-map correction depends on metadata being correct. A technically successful FUGUE command with the wrong phase-encoding axis or dwell time can make geometry worse, not better.

How EDNiX creates those outputs

  1. EDNiX resolves the session’s fMRI directory tree through Tools/getpath.py.
  2. It searches for BOLD runs matching the configured suffix, verifies their length, and reads timing/distortion metadata from BIDS sidecars when available.
  3. It classifies the field-map situation and resolves an anatomy bridge before any numbered stage is called.
  4. It dispatches Steps 1, 2, 3, itk_1, 5, itk_2, optional 6, then 7–12, launcher key 13, itk_3 and optional Clean.

What should I inspect?

If the launcher chooses the wrong BOLD run, anatomy, TR, slice timing or field-map route, every later filename can still look plausible. Check the launcher log before debugging later registration or denoising stages.

Core preprocessing
Why this stage exists

This stage cleans up the acquisition-level time series before anatomy or template registration: discard unwanted volumes, despike, correct slice timing, estimate motion, create censor/motion regressors, and build robust run-mean images.

How EDNiX creates those outputs

  1. 3dTcat removes an optional user-specified volume interval first, then removes the configured T1-equilibration volumes.
  2. 3dDespike attenuates transient voxelwise spikes.
  3. 3dTshift applies slice-timing correction when timing information is available; otherwise EDNiX copies the despiked series and logs a warning.
  4. ANTsPy motion_correction with BOLDRigid aligns every volume to the run mean and stores one affine transform per volume.
  5. EDNiX converts those affines into motion parameters and framewise displacement (FD). Rotations are converted to mm on a sphere with the volume of the brain, and the censoring threshold scales with the same radius: 0.5 mm for a 1200 cm³ human brain, about 0.2 mm for a macaque, 0.04 mm for a mouse. No cross-species FD threshold is established in the literature: report the censored fraction per species. When the orientation fix changes the image frame, the motion matrices are re-estimated in the reoriented frame so that rotations are applied about the right axes.
  6. A post-motion mean is created and passed through adaptive N4 bias correction to produce a stable registration image.

What should I inspect?

Inspect the motion-corrected BOLD, the N4 run mean, censor fraction, motion_enorm and outcount traces. A clean-looking mean does not guarantee acceptable motion.

What happens next? Step 2 prepares field-map correction when available and aligns all runs to one functional reference run.

How EDNiX creates those outputs

  1. The launcher’s field-map state determines whether EDNiX does no correction, prepares one field map, handles a two-map direction pair, or selects from a newer multi-map layout.
  2. _2a_correct_img.py stabilizes the field-map acquisition, concatenates the appropriate opposite-PE images, forces even spatial dimensions for TOPUP, estimates the susceptibility field with TOPUP, converts the field from Hz to rad/s, and creates a magnitude image for QC.
  3. FUGUE then applies that TOPUP-derived field to the Step-1 N4 run mean (effective echo spacing DwellT from EffectiveEchoSpacing, or TotalReadoutTime / (ReconMatrixPE − 1)), producing the unwarped mean, and saves its voxel-shift map (*_desc-runMean_fugue_shift.nii.gz). The full BOLD is not unwarped here: sdc_field.py turns the shift map into an ANTs displacement field that Step 5 applies to every volume in its single interpolation.
  4. _2b_fix_orient.py makes the corrected mean and full BOLD orientation consistent.
  5. ANTs rigid registration aligns each run mean to the reference run and applies that run-to-reference transform to the full run.

What should I inspect?

The most important check is that every run mean overlaps the reference run after this stage. Distortion correction can improve geometry but cannot rescue an incorrect phase-encoding direction or dwell time.

What happens next? Step 3 averages the aligned run means and creates a functional brain mask plus functional-resolution anatomical resources.

How EDNiX creates those outputs

  1. Nilearn combines the aligned run means into one all-runs functional mean.
  2. The selected anatomical reference and its masks are resampled to the functional voxel size so anatomy-derived nuisance masks have the same resolution as BOLD.
  3. If anatomy and fMRI share the same coordinate frame, the anatomy mask can be transformed directly into functional space.
  4. Otherwise Skullstrip_func.py dispatches the configured method and writes the same canonical <ID>_fMRI_mask.nii.gz contract regardless of algorithm.
  5. An optional intensity-aware edge erosion can refine the mask after its initial creation.

What should I inspect?

Overlay <ID>_fMRI_mask.nii.gz on all_runs_space-func_desc-fMRI_Mean_Image.nii.gz. The mask should contain brain consistently without swallowing large non-brain regions or cutting cortex.

How EDNiX creates those outputs

  1. The accepted functional mask is multiplied with the all-runs mean to form the skull-stripped functional reference.
  2. The session mean is brought to the anatomy: with anat_func_same_space=True by the anatomy’s ACPC matrix, otherwise by a rigid ANTs registration. With do_anat_to_func=True a second registration (registration_type = origin / fast / V2, type_of_transform) is estimated; for a non-linear type it is restricted to the phase-encoding axis (weight 1 along it, 0.1 on the others; sdc_field.pe_restriction), the usual correction when no field map exists. With the default 'BOLDAffine' it is affine only. Anatomy masks and atlas labels are then propagated into the functional ACPC frame with label-safe interpolation.
  3. For each run, sdc_field.run_field converts the Step-2 shift map into a displacement field (*_desc-sdc_1Warp.nii.gz + JSON report). Its sign is checked by reproducing FUGUE’s corrected image; the field is dropped if it does not match or if the distortion stays below 0.1 voxel. One field per run with recordings='new'; the reference run’s field for 'old' and '2_mapdir'. The log states SDC ... status ok per run; EDNIX_SDC=0 disables it.
  4. transfo_for_func.py splits the 4D series in memory and applies, per volume, its Step-1 motion matrix, the distortion field, the run-to-reference and ACPC transforms in one interpolation, then writes the 4D image with the original TR. A mismatch between the number of volumes and of motion matrices stops the run.
  5. The transformed 4D series is multiplied by the propagated functional mask to create the canonical Step-5 skull-stripped run.

What should I inspect?

The anatomy, all-runs functional mean, G/W/V masks and atlas labels should agree in acpc-func space before any signal regression is trusted.

How EDNiX creates those outputs

  1. First EDNiX creates temporal QC maps and optional tissue/global nuisance time series.
  2. AFNI mode builds a GLM design with 3dDeconvolve and performs regression/censoring with 3dTproject.
  3. Grandjean mode concatenates motion/tissue nuisance signals, performs simultaneous regression + band-pass (and optional blur) with 3dTproject, then restores the temporal mean.
  4. fMRIPrep_style builds the 24-parameter motion model (Friston et al. 1996), aCompCor components of WM and CSF (Behzadi et al. 2007; voxel time series high-passed with the cosine basis before the PCA, as fMRIPrep), optional global signal and custom confounds, saves them to *_confounds_fMRIPrep_style.tsv, then runs 3dTproject with the temporal filter. No DCT drift regressors are added: the 3dTproject filter already removes those frequencies. acompcor_mode: 'fixed' (default, 5 per tissue), 'adaptive' (components up to acompcor_variance, capped at acompcor_max; in practice the cap is almost always reached) or 'parallel' (components above phase-randomised surrogates; a diagnostic, its null is not calibrated for autocorrelated noise).
  5. Safeguards: a WM or ventricle mask under 10 voxels at functional resolution is not used (recorded per run in *_tissue_regressors.json, so models can differ between subjects and species); the header TR is checked against the analysis TR before filtering (a mismatch stops the run); the degrees of freedom left (uncensored volumes − regressors − filter regressors) are logged, below 20 % of the volumes is a warning and none left is an error.
  6. If do_not_correct_signal=True, the active input is simply copied to the canonical residual filename. Optional z-score or percent-signal-change normalization is then applied.

What should I inspect?

This is where “preprocessed BOLD” becomes an analysis-ready residual. Inspect censor fraction, design matrix/regressors, the degrees of freedom line of the log, *_tissue_regressors.json, residual time series and tSNR. With several species, match run duration, not volume count: a 0.01–0.1 Hz band keeps about 2 × 0.09 × duration independent samples. A residual file existing is not evidence that the regression model was sensible.

How to read JSON sidecars and transform files

EDNiX writes many NIfTI derivatives with adjacent JSON provenance. Transform files are equally important: they explain how a voxel moved, not just what a derivative is called.

NIfTI + JSON

Many stages write a JSON next to the NIfTI with source paths, a description and sometimes the exact command. Treat the pair as one derivative.

Current-code notes worth knowing

These details are deliberately separated from the beginner flow. They matter when maintaining or debugging the implementation, but they should not obscure the conceptual processing route above.

Numbering: the launcher has no ordinary numeric Step 4. The module _4_check_mask.py is invoked by the string skip key itk_1. Later, numeric Skip_step=13 dispatches _14_fMRI_QC_matrix.py.
  • Step 3 QC directory spelling differs: the code creates QC/check_mask_fMRI but the plotting call writes to QC/check_fmri_mask. On a case-sensitive filesystem, the latter directory must exist or the plot may fail.
  • Custom confounds path mismatch: the launcher writes *_confounds_correct.tsv into func/acpc-func/ (dir_prepro_orig), while the AFNI and fMRIPrep-style branches in Step 7 look for that file inside func/acpc-func/postprocessed_*. Unless it is copied there elsewhere, those custom confounds will not be discovered by the current Step-7 code.
  • Reference-run index semantics need care: most functional stages use RS[REF_int], but the single-fieldmap compatibility check in the launcher uses RS[int(REF_int)-1]. With the default REF_int=0, that check indexes the last run.
  • MELODIC accepted values: active execution branches are MELODIC and Skip. The error message also names ICA-ARMOA, but no ICA-ARMOA branch is implemented in _6_Melodic.py.
  • MELODIC second pass: the selection-reuse bug of the earlier snapshot is fixed (1-based melodic_select_1based.txt). The second, combined MELODIC pass still names its output from the last value of root_RS while its input is every *_norm_final_clean.nii.gz of the folder; check which runs it contains when run stems differ.
  • itk_1 modification test is not a true before/after comparison of the same file: when a manual final mask already exists, _4_check_mask.py compares the final mask's post-session mtime against the active preprocessing mask's ctime. Treat automatic detection of a reused old final_mask cautiously.
  • Step 10 can mutate the functional atlas: when atlas and residual grids differ, _10_Correl_matrix.py resamples the atlas and writes it back to the same atlas_filename before ROI extraction. Matrix generation can therefore alter the on-disk functional-space atlas grid.
  • fMRI _200 is not analogous to ANAT _200: the current functional _200_Data_QC.py is a passive ITK-SNAP template overlay; it does not implement the ANAT-style mask-edit/rerun cascade.
  • Cleanup is intentionally irreversible: _100_Data_Clean.clean() requires the literal response YES. It removes the large preprocessing workspaces needed to rebuild Steps 7–12 while preserving residuals, Stats, raw masks/matrices and QC.
  • Stale code comment: the header comment of the fMRIPrep_style branch in _7_post_TTT.py still lists “DCT drift regressors”; the code adds none (see Step 7).
  • Fixed since the September snapshot: Step 5 non-linear func→anat registration is active again (it was commented out, so do_anat_to_func=True silently applied an identity); a volume / motion-matrix count mismatch now stops the run; the Step-5 provenance JSON is named <output>.json; _12_fMRI_QC.py no longer emits a SyntaxWarning.
  • Stable interfaces beat method names: algorithms can change, but the canonical functional mask, residual, atlas and QC paths are the contracts consumed downstream.
