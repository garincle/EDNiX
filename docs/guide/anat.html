EDNiX · ANATOMICAL MRI

How EDNiX turns BIDS anatomy into final volumes, masks, surfaces and QC

This page is written for two readers at once: a beginner who wants to understand what happens to their T1w/T2w data, and a developer who needs to know which script creates which file. The workflow is explained in execution order, not folder order.

Source-of-truth rule: stage order, filenames, directory structure and rerun behaviour on this page were checked against the EDNiX repository (modalities/anat, Tools/getpath.py, master, 13 November 2026). When the code and this page disagree, the code wins: update the stage’s input/output table first. Every parameter is listed in the anatomical parameter reference.

How to read this pipeline

Each stage uses the same structure: why it exists, what it reads, what it creates, how those outputs are created, what to inspect, and what consumes the result next.

FILE = concrete on-disk file/patternSETTING = runtime configurationSTATE = in-memory routing/controlSIDE EFFECT = rerun or deletion
Three names matter: <ID> is the subject identifier used internally, <Timage> is an anatomical contrast such as T1w or T2w, and <type_norm> is the contrast selected as the registration/normalization reference.
“Final” does not mean the same thing at every point. Files containing desc-SS-step1 and desc-SS-step2 are intermediate skull-stripped anatomies. The canonical final subject anatomy created in Step 8 is <ID>_space-acpc_desc-SS_<Timage>.nii.gz.

Where EDNiX writes anatomical files

For each subject/session, Tools/getpath.py defines the anatomical derivative tree below the session’s anat directory.

<data_path>/anat/ ├── preprocessing/ working images, bias correction, FreeSurfer-prep NIfTIs ├── matrices/ ACPC/template affine and warp transforms ├── native/ │ ├── volumes/ canonical ACPC/native anatomical volumes │ │ ├── masks/ brain/tissue masks and manual overrides │ │ └── labels/ 4FS and atlas segmentations │ └── surfaces/ Workbench/GIFTI native and standard-mesh products ├── freesurfer/ │ └── <ID>/ │ ├── mri/ orig.mgz, brain.mgz, wm.mgz, aseg.mgz, filled.mgz… │ ├── surf/ white, pial, sphere, inflated, mid surfaces… │ ├── label/ cortical labels / annotations │ ├── stats/ FreeSurfer statistics │ └── scripts/ ├── templates/ │ ├── <reference>/volumes/ subject↔reference derivatives │ ├── studyTemplate/volumes/ when study-template routing is enabled │ └── refSession/volumes/ when longitudinal routing is enabled └── QC_anat/ final automated anatomical QC <bids_dir>/sty_template/ cohort-level study-template workspace ├── derivatives/tmp/ template construction working files └── derivatives/acpc/ template transforms / volumes / masks / labels

Which reference does Step 6 use?

This routing decision is one of the easiest parts of the pipeline to misunderstand. Loop 2 chooses the target before Steps 5–6.

No longitudinal registration + no study template

The subject registers directly to the EDNiX/reference brain.

source = EDNiX / BASE_SS

No longitudinal registration + study template

The subject registers to the cohort’s study template.

source = studyTemplate

Longitudinal, earlier session

The earlier session registers to the subject’s maximum/latest session.

source = refSession

Longitudinal, max/latest session

The max session becomes the longitudinal anchor, then targets the study template if present, otherwise the EDNiX/reference brain.

source = studyTemplate or EDNiX

modalities/anat/_0_Pipeline_launcher.py
Orchestration
Why this stage exists

Before any image is changed, EDNiX resolves which subjects and sessions will run, which anatomical contrast is the normalization reference, which atlas/template is available, which skull-stripping methods are selected, and which stages should be skipped.

Reads / prerequisites
SETTING<bids_dir>Root of the BIDS dataset.
DATAsubject/session table + keep/remove listsDefines which subject/session pairs are processed.
SETTINGtype_norm / otheranat / masking_imgNormalization contrast, optional second contrast, and image used to estimate the brain mask.
SETTINGreference / species / atlas settingsChooses EDNiX reference resources and atlases.
SETTINGSkip_stepList of numeric stages or named checkpoints to skip.
Creates / changes
STATEall_ID, all_Session, all_data_pathResolved subject/session processing list.
STATEBASE_SS, BASE_mask, BASE_atlas_folderResolved reference brain, mask and atlas resources.
STATElist_transfoNormalized transform configuration used by later registration stages.
STATELoop 1 → optional study-template block → Loop 2 → optional Step 7 → Loop 3Actual execution plan.

How EDNiX creates those outputs

  1. Normalizes anatomy labels such as T1/T1w and T2/T2w.
  2. Loads AFNI, FSL, FreeSurfer, ITK-SNAP, Workbench and other configured runtimes.
  3. Builds the optional study-template workspace at <bids_dir>/sty_template.
  4. Dispatches each subject/session through Loop 1, then the cohort-level branch if requested, then Loop 2 and Loop 3.

What should I inspect?

At this point no anatomical derivative should be interpreted as processed. This stage only decides what will run and where resources come from.

What happens next? Loop 1 begins with Step 1 for every selected subject/session.

Prepare, average and orient the anatomy

modalities/anat/loop1/_1_correct_orient.py
Core stage
Why this stage exists

Raw anatomical scans can have different orientation, obliquity, repeated acquisitions and intensity bias. EDNiX first turns them into a stable set of subject-specific inputs before masking or registration.

Reads / prerequisites
FILE<data_path>/anat/sub-<ID>_ses-<Session>_*<Timage>.nii*BIDS anatomy for BIDStype=1. Other BIDStype patterns are supported.
FILEmatching .json sidecarsUsed when available to inspect acquisition metadata and filter repeated scans.
SETTINGorientationRequested output orientation, for example LSP/LPI depending the study.
SETTINGMNIBcorrect_indivBias correction choice: N4, N3, or configured alternative.
Creates / changes
FILEanat/preprocessing/<ID>_space-raw_desc-template_<Timage>.nii.gzOne stable image per contrast. A single scan is copied; repeated scans can be robustly averaged.
FILEanat/preprocessing/<ID>_space-raw_desc-reorient_<Timage>.nii.gzDeobliqued/reoriented working image.
FILEanat/preprocessing/<ID>_space-raw_desc-Bias_<Timage>.nii.gzBias-field-corrected image used by Step 2.
FILEanat/preprocessing/<ID>_space-raw_desc-template_T1wdividedbyT2w.nii.gzOptional T1/T2-derived myelin-like image when both contrasts are available/configured.
FILEmatching .json filesProvenance sidecars describing sources and operations.

How EDNiX creates those outputs

  1. EDNiX discovers the requested T1w/T2w files from the BIDS anatomy folder.
  2. If one usable image is found, it becomes the working template. If several are found, the current code can use FreeSurfer mri_robust_template to co-register and average them.
  3. AFNI checks obliquity and orientation; the image is deobliqued/copy-adjusted and its orientation header is set as configured.
  4. If two anatomical contrasts are present, the secondary image is resampled to the normalization contrast when needed.
  5. ANTsPy performs N4/N3 bias correction and writes the desc-Bias image.

What should I inspect?

Check orientation before continuing. A left/right or anterior/posterior error here contaminates every downstream transform.

What happens next? Step 2 skull-strips the desc-Bias image and creates the first ACPC-space products.

modalities/anat/loop1/_2_clean_anat.py
Core stage
Why this stage exists

This stage estimates a first brain mask and establishes the subject’s working ACPC-style space. It is deliberately an early, conservative mask because later stages refine it.

Reads / prerequisites

FILEanat/native/volumes/<ID>_space-acpc_desc-template_<Timage>.nii.gzUnmasked ACPC anatomical template for each contrast.
FILEanat/native/volumes/<ID>_space-acpc_desc-SS-step1_<Timage>.nii.gzStep-1 skull-stripped ACPC anatomy.
FILE<bids_dir>/QC/skullstrip_step1/...pngSkull-strip QC mosaic.
FILE<bids_dir>/QC/align_rigid_to_template/...pngAlignment QC mosaic.

How EDNiX creates those outputs

  1. The shared Skullstrip_method dispatcher creates <ID>_desc-step1_mask.nii.gz. A correctly named manual mask can override the automatic method.
  2. 3dcalc multiplies the mask with the normalization anatomy to create a brain-only registration target.
  3. The configured ACPC/reference alignment is estimated. The code can also use an identity/copy route when alignment is disabled.
  4. 3dAutobox crops the aligned image, and the first mask is resampled onto that grid.
  5. Every anatomical contrast is resampled into the same ACPC grid, written as desc-template, then multiplied by the ACPC mask to create desc-SS-step1.

What should I inspect?

Inspect both the skull-strip mosaic and rigid-alignment mosaic. Step 1 products are still intermediate and are expected to be refined.

What happens next? The itk_1 checkpoint lets a human correct the first mask. If edited, Step 2 is automatically rerun.

Manual QC gate for the first mask

modalities/anat/loop1/_itk1_QC.py
Manual QC
Why this stage exists

Automatic skull stripping is not trusted blindly. The first mask can be inspected and corrected before it contributes to a study template or later registration.

Reads / prerequisites
FILEanat/preprocessing/<ID>_space-raw_desc-Bias_<type_norm>.nii.gzGreyscale image displayed in ITK-SNAP.
FILEanat/native/volumes/masks/<ID>_desc-step1_mask.nii.gzCurrent segmentation layer.
Creates / changes
FILEanat/native/volumes/masks/<ID>_final_mask.nii.gzManual override, only when the user saves one under this exact name.
STATEmask_was_updated=True/FalseTells Loop 1 whether the correction changed the pipeline state.
SIDE EFFECTStep 2 rerun when editedThe corrected mask is copied/resampled into the active Step-1 mask and Step 2 is regenerated.

How EDNiX creates those outputs

  1. ITK-SNAP opens the anatomy and current Step-1 mask.
  2. The code records the manual mask modification time before and after the viewer session.
  3. If <ID>_final_mask.nii.gz is created or modified, the checkpoint reports an update.
  4. Loop 1 reruns Step 2 so all ACPC/template and skull-stripped products inherit the correction.

What should I inspect?

Saving under a different filename does not activate the override. The exact canonical filename matters.

What happens next? After all subjects finish Loop 1, EDNiX either builds an optional study template (Steps 3–4) or goes directly to Loop 2.

Study-template only
Why this stage exists

A cohort-specific template can reduce the anatomical mismatch between the study population and a generic atlas. This is a group-level stage, not a per-subject stage.

Reads / prerequisites
FILEanat/native/volumes/<ID>_space-acpc_desc-SS-step1_<type_norm>.nii.gzStep-1 skull-stripped anatomy from selected subjects/sessions.
SETTINGwhich_on = all or maxChooses all eligible sessions or one/max session per subject for template construction.
Creates / changes
FILE<bids_dir>/sty_template/derivatives/tmp/<ID>_space-acpc_desc-SS-step1_<type_norm>Zp.nii.gzZero-padded/common-grid subject image used during template building.
FILE<bids_dir>/sty_template/derivatives/tmp/warped_3_adjusted_mean.nii.gzGroup mean produced by the template-building routine.
FILE<bids_dir>/sty_template/derivatives/tmp/studyTemplate_<type_norm>.nii.gzUnmasked study template image prepared for Step 4.

How EDNiX creates those outputs

  1. EDNiX selects the Step-1 skull-stripped subjects specified by which_on.
  2. A reference image is zero-padded and the other subject images are resampled to a compatible grid.
  3. anat_to_common_EMB iteratively aligns the selected anatomies and creates a cohort mean.
  4. The group mean is written into the sty_template temporary workspace for skull stripping.

What should I inspect?

This stage only runs when creat_study_template=True. A poor Step-1 mask can influence the group template, which is why itk_1 occurs beforehand.

What happens next? Step 4 estimates the study-template brain mask and creates its skull-stripped version.

modalities/anat/loop2/_6_stdyTmax.py
Core stage
Why this stage exists

EDNiX now connects the subject’s ACPC anatomy to the spatial reference used for labels and group comparisons. The target is route-dependent.

Reads / prerequisites
FILEanat/native/volumes/<ID>_space-acpc_desc-SS-step2_<type_norm>.nii.gzMoving subject anatomy.
ROUTEstudyTemplate_<type_norm>.nii.gzTarget when creat_study_template=True and the current session is not routed to a longitudinal refSession.
ROUTEmax/latest session desc-SS-step2 anatomyTarget for earlier sessions when coregistration_longitudinal=True.
ROUTEBASE_SSTarget when using the EDNiX/reference route.
Creates / changes
FILEanat/matrices/native_to_<source>_Final_0GenericAffine.matCore affine transform.
FILEanat/matrices/native_to_<source>_Final_1Warp.nii.gzOptional nonlinear forward warp when the configured transform generates one.
FILEanat/matrices/native_to_<source>_Final_1InverseWarp.nii.gzOptional inverse warp.
FILEanat/templates/<source>/volumes/native_space-<source>_desc-SS_<Timage>.nii.gzSubject anatomy transformed into the selected reference space.
FILEanat/templates/<source>/volumes/<source>_space-native_desc-SS_<Timage>.nii.gzReference anatomy transformed back toward subject/native space for checking.
FILE<bids_dir>/QC/native_to_<source>_<Timage>/...pngForward and reverse registration QC mosaics.

How EDNiX creates those outputs

  1. norm2template.norm estimates the configured coregistration transform between subject and target.
  2. If a nonlinear warp exists, EDNiX builds affine+warp forward/inverse lists; otherwise it uses the affine alone.
  3. norm2template.apply sends every anatomical contrast forward to the reference and backward to native/ACPC space.
  4. QC mosaics are generated in both directions.
  5. Optional SyNadaptive (coreg block, experimental): the standard SyNCC is run and checked inside the template brain (Dice of brain masks, Dice of a 3-class k-means tissue split, fraction of folded voxels). Only if a check fails is a more compliant, brain-masked SyN tried from the same affine; it replaces SyNCC only if tissue overlap improves by > 0.01 without folding. The decision is written to <prefix>_adaptive_QC.json next to the transforms. On the BIDS_Park calibration (n = 5, recon-all aseg as independent labels) the refinement lowered label Dice, so SyNCC remains the default.

What should I inspect?

The target name matters when reading filenames: <source> may be studyTemplate, refSession or EDNiX/reference.

What happens next? If a study template exists, Step 7 connects it to the atlas. Otherwise the pipeline proceeds to Loop 3 / Step 8.

How EDNiX creates those outputs

  2. Template/reference masks and labels are inverse-transformed into the subject ACPC grid.
  3. For the normalization contrast, the final mask is applied to the desc-template image with 3dcalc to create <ID>_space-acpc_desc-SS_<Timage>.nii.gz.
  4. If a manually edited backtonative mask already exists, it takes priority over the automatic ACPC mask.
  5. Atlas/4FS outputs are resampled with label-aware handling and the temporary space-acpc token is removed from canonical label/mask filenames at the end.

Hemisphere and subcortical labels are kept; if GM and WM are not separable (Fisher distance < 1) the registration labels are kept. Calibration on BIDS_Park (n = 5, recon-all aseg as reference): mean label Dice +0.025 in 5/5 subjects; not yet validated in non-human species, and it degraded Rat and Marmoset in tests (low GM/WM contrast).

Batch runs, resets and QC reports

Three tools sit around the step dispatcher. None of them changes how a stage works; they decide what runs, what is deleted before a rerun, and how QC is gathered.

Reset before a rerun

Every example launcher has RESET_BEFORE_RUN / RESET_DRY_RUN. The anatomical cleaner removes everything EDNiX wrote under anat/ (or only freesurfer/ + native/surfaces/ with RESET_SCOPE='surfaces', to rerun Steps 10–15) and keeps the raw BIDS files and every manual file: *_final_mask* (itk_1/itk_2), *_backtonative_mask* (itk_3), *_desc-manual*, segmentation.mgz, *.scene. A dry run lists the files first; deletion needs one YES.

modalities/anat/_000_Data_Reset.py

All launchers as a dependency graph

Per BIDS folder: anat before CT, CT before PET, anat before func; then the QC reports of every dataset and a study-level Excel summary. Launchers run with their own Skip_step; a launcher is split by subject into workers within the machine’s cores; a job whose prerequisite failed is not started. --plan shows the jobs without running anything.

Exemples/Study_EDNiX/run_all_ednix.py

Full rebuild

Builds the V2 atlas library, checks it against its manifest, swaps the libraries, resets the BIDS folders (manual masks and crops kept), then runs run_all_ednix.py detached, after one confirmation.

Exemples/Study_EDNiX/rebuild_all_ednix.py

QC reports at three levels

Gathers existing QC (nothing is recomputed): one HTML page per subject/session, QC/QC_all_subjects.html (values beyond 3.5 robust SD from the median highlighted), QC/QC_dataset.html and QC/EDNiX_BIDS_summary.xlsx. Run by run_all_ednix.py or python -m Tools.QC_report <BIDS>.

Tools/QC_report.py
Strict mode: without EDNIX_STRICT=1 a failing external command is logged in red and the pipeline continues. Use strict mode for a new species, a new dataset and every validation run. Details: launchers.md, quality_control.md.

Manual override rule

If the correctly named manual final mask already exists, the dispatcher prioritizes it and can bypass automatic skull stripping.

<ID>_final_mask.nii.gz / <ID>_final_mask_2.nii.gz
Developer implication: the same stage can produce a mask through very different algorithms depending on configuration. Documentation should describe the stage contract (input mask image → output mask) separately from the selected implementation.

Developer map: orchestration vs processing vs libraries

The folder contains many Python files, but they are not all sequential stages. Keeping these roles separate makes the codebase much easier to navigate.

Orchestration

Decides order and routing; should not be described as if it directly creates every image.

_0_Pipeline_launcher.py · _loop1.py · _loop2.py · _loop3.py

Numbered processing modules

Implement the stage contracts documented above.

_1_correct_orient.py · _2_clean_anat.py · _3_make_template.py …

Manual QC gates

Interactive checkpoints whose edits deliberately trigger regeneration.

_itk1_QC.py · _mask2_Data_QC.py · _200_Data_QC.py

Shared method libraries

Algorithms selected by configuration rather than independent pipeline stages.

skullstrip/* · norm2template.py · freesurfer/* · connectomeWB/*

Path contract

The directory tree is centralized here. Read this before inventing or documenting a path.

Tools/getpath.py

Provenance contract

Many NIfTI derivatives receive adjacent JSON sidecars recording sources and descriptions. The sidecars are part of understanding how a file was made.

*.nii.gz ↔ *.json
Recommended maintenance rule: when the code changes, update the stage’s input/output table first, then its algorithm description. That keeps the documentation useful even when an implementation method is replaced.
